### 1.2 İçerik (3 blok)

**Blok 1 — Fix #1: `_etken_kod_bul` E_VIT eşleşmesi (L9213)**

`v_active_ing ILIKE '%E Vitamini%'` kontrolünü **mevcut E_VIT satırından ÖNCE** ekle (en spesifik kontrol önce):

```sql
-- Önce (yeni, daha spesifik):
IF v_active_ing ILIKE '%E Vitamini%' THEN RETURN 'E_VIT';

-- Mevcut (korunur, fallback):
IF v_class_name ILIKE '%E Vit%' OR v_stok_ad ILIKE '%yeldif%' OR v_stok_ad ILIKE '%e vit%' THEN RETURN 'E_VIT';
```

**Blok 2 — Fix #2: `hizli_uygulama` islem_log audit (L9256-9306)**

⚠️ **GERÇEK İMZA (Faz 0.2 doğrulaması):** `hizli_uygulama` 6 parametreli (p_hayvan_id, p_stok_id, p_doz, p_birim, p_rota, p_notlar) → `jsonb` döner. Spec Rev 7'deki 11 parametreli imza YANLIŞ'tı (arşiv: `docs/ideas/2026-06-10-hizli-uygulama-genisletilmis-imza.md`).

3 JS caller (`js/ui.js` L951, L1090, L3978) `p_rota` kullanıyor ve `res.ok`/`res.mesaj` dönüş yapısına bağımlı — mevcut yapıyı KORU.

`uygulama_log` INSERT'inden sonra (RETURNING id INTO v_id), `stok_hareket` INSERT'inden önce `islem_log` INSERT ekle. `gorev_tamamla` L6596 referans pattern'i:

```sql
INSERT INTO public.islem_log (tip, ana_hayvan_id, ref_id, ref_tablo, snapshot, kullanici_notu)
VALUES (
  'HIZLI_UYGULAMA',
  p_hayvan_id,
  v_id::text,
  'uygulama_log',
  jsonb_build_object(
    'olusturulan', jsonb_build_array(jsonb_build_object('tablo','uygulama_log','id',v_id::text)),
    'guncellenen', '[]'::jsonb,
    'silinen', '[]'::jsonb
  ),
  format('Hızlı Uygulama — %s — %s %s', v_hayvan.kupe_no, v_stok.urun_adi, p_doz)
);
```

**Blok 3 — Bonus: `hizli_uygulama_geri_al` islem_log audit (L9309-9342)**

⚠️ **YERLEŞİM KRİTİK + FAZ 0 DOĞRULAMASI:** 
- `v_uyg.hayvan_id` kullan (L9317'de record'a alınmış) ✅
- INSERT'i **L9338 DELETE'den ÖNCE** koy ✅
- ⚠️ **`v_hayvan` değişkeni bu RPC'de DECLARE edilmemiş olabilir!** Format'ta `v_hayvan.kupe_no` runtime error verir
- **Faz 0'da DOĞRULA:** `pg_get_functiondef('hizli_uygulama_geri_al')` çıktısında `v_hayvan` DECLARE var mı kontrol et
- **Güvenli alternatif:** `v_uyg` record'unda `kupe_no` kolonu var mı kontrol et. Varsa `v_uyg.kupe_no` kullan, yoksa sadece `v_uyg.aktif_ing` ile minimal format:

```sql
-- L9336 ile L9338 arasına (gorev_log UPDATE sonrası, uygulama_log DELETE öncesi):
INSERT INTO public.islem_log (tip, ana_hayvan_id, ref_id, ref_tablo, snapshot, kullanici_notu, durum, geri_alma_tarihi)
VALUES (
  'HIZLI_UYGULAMA_GERI_AL',
  v_uyg.hayvan_id,  -- L9317'de okunan record (DELETE'den ÖNCE!)
  p_uygulama_id,
  'uygulama_log',
  jsonb_build_object(
    'olusturulan', '[]'::jsonb,
    'guncellenen', jsonb_build_array(jsonb_build_object('tablo','gorev_log','id',v_uyg.gorev_id,'alan','tamamlandi','eski',true,'yeni',false)),
    'silinen', jsonb_build_array(jsonb_build_object('tablo','uygulama_log','id',p_uygulama_id))
  ),
  -- Rev 7 düzeltme: v_uyg.aktif_ing kolonu YOK (Faz 0 doğrulaması)
  -- v_hayvan DECLARE mevcut (L8) → v_hayvan.kupe_no güvenli
  format('Hızlı Uygulama Geri Al — %s — uygulama_id=%s', v_hayvan.kupe_no, p_uygulama_id),
  'geri_alindi',
  now()
);
```

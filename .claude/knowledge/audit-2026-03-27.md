## 🔴 HATALAR / SORUNLAR

### H1 — rpcOptimistic imza uyumsuzluğu (KRİTİK)
- **Konum:** ui.js:2583
- **Önem:** Kritik
- **Durum:** yeni
- **Açıklama:** `rpcOptimistic(()=>..., ['tohumlama','hayvanlar'])` şeklinde çağrılıyor. Fonksiyon imzası `rpcOptimistic(name, params, opts)` — 1. parametre string RPC adı bekliyor. Callback hiç yürütülmüyor; tohumlama "Gebe" işaretleme DB'ye yazılmıyor.
- **Fix:** `await rpcOptimistic('tohumlama_sonuc_gebe', { p_toh_id: son.id })`
- **İlgili:** api.js:264 (rpcOptimistic tanımı)

## Web Araştırması Bulguları (Phase 2)

### Offline Queue + RPC Enforcement
- Service Worker `fetch` event intercept → başarısız RPC'ler IndexedDB'ye yazılır, reconnect'te replay
- Supabase Realtime Postgres Changes ile reconnect sync otomatikleştirilebilir
- CRDT gerekmez — basit sıralı kuyruk yeterli (EgeSüt için)

### Duplicate Detection
- Module Pattern + `window.app = { ui: {}, api: {} }` namespace
- Custom Node.js AST parser script: `acorn` ile parse et, fonksiyon isimlerini karşılaştır
- ESLint `no-dupe-keys` bu durumda işe yaramaz (global scope)

### ADR Format (MADR)
- Standart: Title, Status, Context, Decision, Consequences, Alternatives
- `.claude/arch-decisions/ADR-001.md` formatı uygun
- Status: Proposed | Accepted | Superseded | Deprecated
